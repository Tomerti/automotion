# Regex Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two new walkthroughs: a typed regex becomes an NFA by Thompson's construction, and the
open automaton becomes a regex by state elimination, with an optional student-picked order.

**Architecture:** `core/regex.ts` parses and prints the course's regex syntax into an AST.
`core/thompson.ts` (+ `thompsonLayout.ts`) and `core/eliminate.ts` compute whole traces eagerly,
like `subset.ts` and `minimize.ts`, each with a `can*` guard. Two new trace kinds join `AnyTrace`;
the player, a view per kind, and the store's trace lock are reused. The Thompson trace has no
source automaton, so the few `trace.source.id` reads go through one helper.

**Tech Stack:** TypeScript (strict, `noUncheckedIndexedAccess`), React 19, Zustand + immer, Vitest +
fast-check + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-regex-design.md` (read it first; this plan argues from it).

## Global Constraints

- `core/` imports nothing outside `core/`; no React there. Nothing outside `ui/` imports `ui/`.
- Syntax: `|` union, `+` one or more, `*` zero or more, juxtaposition concatenates, `( )`, `ε`
  (typed `\eps`), `∅` (typed `\emptyset`). No `?`. Whitespace between tokens is ignored.
- A regex symbol is any single character (code point) except `| + * ( ) ε ∅ \ ,` and whitespace.
- All indices (`span`, error `at`) are UTF-16 offsets into the **normalised** text (after `\eps` →
  ε, `\emptyset` → ∅), which is what the dialog shows.
- `MAX_THOMPSON_STATES = 64`; `MAX_REGEX_LENGTH = 2000`; arrow labels over 40 characters drawn as
  their first 39 + `…`.
- Thompson states are labelled `q_0`, `q_1`, … in creation order; a union is one node with all its
  branches (one fan); concatenation is left-associative and joined by an ε-arrow, never merged.
- Existing `data-testid`s, accessible names (`Create`, `Convert to DFA`, …) and lesson behaviour
  stay unchanged. Hover styles go inside `@media (hover: hover)`. Colours via theme tokens.
- Run `npm run typecheck && npm run lint && npm test` before every commit; `npm run format` too.

## Review Focus

1. **Non-Latin and astral symbols** (`א|ב`, `😀*`): one code point is one symbol, spans still slice
   the right text. → Task 1 test `astral symbol is one symbol`.
2. **Building from a regex while another trace is open** (a run, a lesson walkthrough): the new
   Thompson trace replaces it, the active automaton stays the same and unlocked once closed. →
   Task 4 test `startThompson replaces an open trace`.
3. **Degenerate regexes `ε`, `∅`, `ε*`, `∅*`**: a valid NFA (no `validate` errors), layout without
   overlap, Save works. → Task 2 test `degenerate regexes build valid NFAs`.
4. **A source automaton with states already labelled `s` or `f`**: the added GNFA states don't
   clash. → Task 6 test `s and f labels don't clash`.
5. **Picking after stepping back**: paused on an earlier step, a click recomputes from there; earlier
   steps unchanged, later states removed in the new order. → Task 6 test `order prefix keeps earlier
   steps` and Task 7 test `picking while paused on an earlier step`.

  ```ts
  export interface Span { start: number; end: number }
  export type Regex =
    | { type: 'sym'; sym: Sym; span?: Span }
    | { type: 'eps'; span?: Span }
    | { type: 'empty'; span?: Span }
    | { type: 'concat'; left: Regex; right: Regex; span?: Span }
    | { type: 'union'; branches: Regex[]; span?: Span } // ≥ 2 branches
    | { type: 'star' | 'plus'; body: Regex; span?: Span };
  export const EMPTY_SET = '∅';
  export function isRegexSymbol(ch: string): boolean;
  export function normalizeRegexText(text: string): string; // \eps → ε, \emptyset → ∅
  export type ParseResult = { ok: true; regex: Regex; text: string } | { ok: false; error: string; at: number };
  export function parseRegex(input: string): ParseResult; // normalises first; `text` is the normalised input
  export function printRegex(r: Regex): string;           // fewest parentheses
  export function regexSymbols(r: Regex): Sym[];          // sorted, unique
  ```
