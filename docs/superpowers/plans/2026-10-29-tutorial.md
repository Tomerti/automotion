# Interactive Tutorial Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A guided, checked-live tutorial in which the user builds the "even number of 0s" DFA,
runs it, then turns it into a one-state DFA accepting every word.

**Architecture:** The steps are a pure table in `src/ui/tutorial/steps.ts` (checks over
`{ automaton, isActive, trace, stepIndex }`) with an `advance()` reducer. A small Zustand store
subscribes to `appStore` while a tutorial runs and keeps progress. A floating coach card and a
pointer ring render it; a welcome dialog replaces the first-visit Controls popup.

**Tech Stack:** TypeScript (strict, `noUncheckedIndexedAccess`), React 19, Zustand, Vitest +
Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-29-tutorial-design.md` (read it first; its step table,
hint list and copy are binding).

## Global Constraints

- All tutorial code lives in `src/ui/tutorial/`; `steps.ts` imports only `core/` and types.
- `useAppStore` / tutorial-store selectors return stable references (primitives or existing
  objects; `useShallow` for derived ones).
- The card takes no keyboard input and never moves focus; S, A, Delete, Esc keep working.
- Colours only through existing tokens in `ui/theme.css`; light and dark both work.
- Keep existing `data-testid`s and accessible names. New ones: `tutorial-card` (with `data-step`
  1–13), `tutorial-pointer`.
- Don't run `npm run format`; run `npx prettier --write <files>` on touched files only.
- Counter copy: `Tutorial · {n} of 12`, and `Tutorial · Done` on step 13.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- The user renames q_0/q_1 mid-tutorial: steps keep working (roles, not labels). Test in Task 2.
- The user switches to another automaton or deletes the Tutorial one: the card says so / the
  tutorial ends, and nothing advances off the wrong automaton. Tests in Tasks 2 and 3.
- The user's undo in part 1 removes q0's start flag after step 5: the card falls back to step 2,
  and `progress` is kept so redoing jumps back. Test in Task 2.
- A run of the right word on a *different* automaton, or one closed before its verdict: never
  latches. Test in Task 2.
- Starting the tutorial twice (Restart from Controls): a fresh automaton named "Tutorial 2" and
  progress reset. Test in Task 3.

### Task 2: Step table and `advance()`

**Files:**
- Create: `src/ui/tutorial/steps.ts`, `src/ui/tutorial/steps.test.ts`

**Interfaces:**
- Consumes: `Gesture` (Task 1); `Automaton`, `State`, `startStates` (`core/model`); `AnyTrace`.
- Produces:

```ts
export interface TutorialContext {
  automaton: Automaton | undefined; // the tutorial automaton, by id
  isActive: boolean;                // it is the active automaton
  trace: AnyTrace | null;
  stepIndex: number;
}
export type StepId =
  | 'add-q0' | 'start' | 'accepting' | 'add-q1' | 'q0-q1' | 'q1-q0' | 'loops'
  | 'run-1010' | 'run-10' | 'delete-q1' | 'loop-01' | 'run-10-again' | 'done';
export type Hint = { kind: 'elsewhere'; name: string } | { kind: 'text'; text: string };
export interface Step {
  id: StepId;
  part: 1 | 2 | 3;               // 3 = the closing card
  instruction(ctx: TutorialContext): string; // `code` in backticks, labels as q_0
  gesture?: Gesture;
  confirmation(ctx: TutorialContext): string; // shown as "✓ …" after it completes
  done(ctx: TutorialContext): boolean;        // structural check; run steps: see runSucceeded
  hint(ctx: TutorialContext): Hint | null;
  target(ctx: TutorialContext): string | null; // CSS selector for the pointer
  run?: { word: string; accepted: boolean };
}
export const STEPS: readonly Step[];  // 13 entries, spec order
export const COUNTED_STEPS = 12;
export function roles(a: Automaton): { q0?: State; q1?: State };
export function runSucceeded(step: Step, ctx: TutorialContext): boolean;
export interface Progress { progress: number; current: number; latched: ReadonlySet<StepId>; completed: StepId | null }
export function advance(progress: number, latched: ReadonlySet<StepId>, ctx: TutorialContext): Progress;
```

Rules the code must follow (from the spec):
- `roles`: q0 = `startStates(a)[0]` else `a.states[0]`; q1 = first state ≠ q0.
- `done` per the spec table; edge checks compare symbol **sets** exactly. `done` of `done` is
  always `false`.
- `runSucceeded`: `ctx.isActive`, `trace?.kind === 'run'`, `trace.source.id === ctx.automaton?.id`,
  `trace.word === step.run.word`, `trace.accepted === step.run.accepted`,
  `ctx.stepIndex === trace.steps.length - 1`.
- `advance` (indices 0-based; part starts at 0, 9, 12):

```
completed = null
loop:
  if !ctx.isActive or !ctx.automaton: current = progress; break     // never advance off-tutorial
  isDone(i) = STEPS[i].run ? latched.has(id) : STEPS[i].done(ctx)
  current = first i in [partStart(progress) .. progress] with !isDone(i)
  if current is defined:
    if STEPS[current].run and runSucceeded(STEPS[current], ctx): latched += id; continue
    break
  if progress == 12: current = 12; break
  completed = STEPS[progress].id; progress += 1
return { progress, current, latched, completed }
```

- Hints: the spec's list, first applicable wins, in this order: elsewhere (`!isActive` →
  `{ kind: 'elsewhere', name }`), trace open on a structural step, extra state (part 1),
  q1 accepting (part 1), NFA, wrong symbols on the asked-for edge, extra arrow (part 1),
  different word run (not when it is the word of the step just before, which is still open),
  step 10 with no states. Copy is the spec's, with labels inserted (`q_0`, not `q0`).
- Targets: `[data-testid="canvas"] [data-state-id="<id>"]`,
  `[data-transition-id="<id>"] [data-testid="edge-label"]`, `input[aria-label="Word"]`.
- Gestures: add-q0/add-q1 `{ mouse: 'double', on: 'empty canvas' }`; start `{ keys: ['S'], on: 'selected state' }`;
  accepting `{ keys: ['A'], on: 'selected state' }`; edges `{ keys: ['Shift'], mouse: 'drag', on: 'q_0 to q_1' }` (labels live);
  loops `{ keys: ['Shift'], mouse: 'drag', on: 'a state onto itself' }`; runs `{ keys: ['Enter'], on: 'in “Test a word”' }`;
  delete `{ keys: ['Delete'], on: 'selected state' }`; loop-01 `{ mouse: 'double', on: 'the loop' }`.

### Task 3: Tutorial store

**Files:**
- Create: `src/ui/tutorial/tutorialStore.ts`, `src/ui/tutorial/tutorialStore.test.ts`
- Modify: `src/store/store.ts` (export `freeName(automata: Automaton[], base = 'Untitled'): string`)

**Interfaces:**
- Consumes: `advance`, `STEPS`, `TutorialContext` (Task 2); `appStore`, `renameAutomaton`.
- Produces:

```ts
export interface TutorialState {
  active: boolean; automatonId: string | null; progress: number; current: number;
  latched: ReadonlySet<StepId>; confirmation: string | null;
}
export const tutorialStore: StoreApi<TutorialState>;
export const useTutorial: <T>(selector: (s: TutorialState) => T) => T;
export function tutorialContext(app: AppState, automatonId: string | null): TutorialContext;
export function startTutorial(): void;
export function endTutorial(): void;
```

- `startTutorial`: end any running one; if the active automaton has no states, rename it to
  `freeName(automata, 'Tutorial')` and set `kind: 'DFA'` via `edit(..., { record: false })`;
  else `createAutomaton('DFA')` then the same rename. `closeTrace()`. Reset progress to 0, then
  subscribe to `appStore`: on each change, end if the automaton no longer exists, else run
  `advance` and store the result; when `completed` is set, store
  `STEPS[index of completed].confirmation(ctx)`. Only `set` when something changed.
- `endTutorial`: unsubscribe, reset to inactive.
