# Lessons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the tutorial into a lesson engine: Basics (today's tutorial, unchanged) plus four short
lessons (NFAs, Convert NFA → DFA, Minimize a DFA, Share and export), listed in a Lessons tab of the
Controls popup.

**Architecture:** A lesson is data (`Lesson` in `ui/tutorial/engine.ts`); the existing tutorial
store, card, pointer, hints and latching run whichever lesson is open. Lessons other than Basics open
on a ready-made automaton that is read-only (a store-level lock that still allows layout moves),
with their walkthroughs paused. Steps can now also complete by a latch (a walkthrough reaching a
point) or by an action the shell reports (Share link, Copy image, …).

**Tech Stack:** TypeScript (strict, `noUncheckedIndexedAccess`), React 19, Zustand + immer, Vitest +
Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-15-lessons-design.md` (read it first; it holds every
lesson's draft steps and why lines). Background: `docs/superpowers/specs/2026-10-29-tutorial-design.md`.

## Global Constraints

- Step instruction: one sentence, at most 100 characters. Why line: one sentence giving the reason,
  at most 110 characters for lessons, 70 for Basics. Markup: `[Key]`, `«state label»`, `` `word` ``.
- A lesson other than Basics has at most 6 counted steps (the closing card not counted).
- Basics keeps every word of today's card and popup: "Part 1 of 2 · Step 3 of 11", "Tutorial ·
  Done", "End tutorial", "Quit the tutorial?", "Back to Tutorial", "Tutorial complete!".
- All `tutorial-*` test ids, `save-and-minimize`, and the card's look stay as they are for every
  lesson.
- Finished lessons live under the localStorage key `automotion:lessons-done` (JSON array of lesson
  ids); no change to the automata file format, autosave, exports or share links.
- `core/` imports nothing outside `core/`; `store/` never imports `ui/`.
- Nothing new on screen while no lesson runs, apart from the Lessons tab and the popup's Next button.
- Confirmations use `askConfirm()`; hover styles inside `@media (hover: hover)`; colours via theme
  tokens; `useAppStore`/`useTutorial` selectors return stable references.
- Lesson order: Basics, NFAs, Convert NFA → DFA, Minimize a DFA, Share and export.
- Every commit passes `npm run typecheck`, `npm run lint`, `npm run format:check` and `npm test`.

## Review Focus

- A walkthrough closed midway in a paused lesson, then reopened: latched steps stay done, the card
  asks to reopen it ("First, press **Convert to DFA** again."), nothing jumps ahead. Test in Task 6.
- The user deletes an owned automaton from the history mid-lesson: deleting the lesson's own
  automaton ends the lesson (as today); deleting a saved one drops it from `owned` and lifts its
  read-only lock. Test in Task 3.
- Reload or end mid-lesson: the read-only lock is in memory only, so nothing stays locked after a
  lesson ends or the page reloads. Test in Task 3 (`endLesson` clears `readOnly`).
- Undo in a read-only automaton: undoing a state move works; nothing can undo past the lesson's
  start into a structural change, and Tidy (a layout change) works. Test in Task 1.
- Starting Basics from the welcome or a lesson row while another lesson is midway asks first; Cancel
  leaves the running lesson untouched. Test in Task 4.

- Produces: `sameStructure(a: Automaton, b: Automaton): boolean` in `core/edit.ts`. True when
  `kind`, `alphabet`, state `id`/`label`/`mergedFrom` (in order), `starts`, `accepting`, and

  `edit` and undo/redo (`swap`) refuse, and bump `blockedEdits`, when the active id is in `readOnly`
  and `!sameStructure(current, next)`; layout-only changes go through as before.
